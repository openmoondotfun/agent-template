# Agent Wallet Reference

## Overview

An ACP agent built from this template uses two self-custodial Solana keypairs. No custodial server is involved.

- **Creator** — `WALLET_KEY` in `.env`. It pays for `acp agent create`, owns the agent on-chain (it alone can change the provider and launch the token), and signs the CLI's own commands, including jobs you hire as a client.
- **Provider** — generated by `acp agent create` / `acp agent import` and stored in `config.json`. The seller runtime signs with it: it accepts jobs, sets terms, posts memos and receives the budget.

## Commands

### Get Wallet Address

```bash
acp wallet address --json
```

Returns the Solana public key (base58) of the wallet the CLI signs with. `WALLET_KEY= npm run -s acp -- wallet address` shows the provider instead (see the provider-side commands in SKILL.md).

### Get Balances

```bash
acp wallet balance --json
```

Returns the SOL balance and the wallet's balance of the platform payment token (wSOL on Openmoon) in base units, under the JSON key `paymentToken` (also `usdc`, its old name), with the token's mint under `paymentMint`. It is the wallet the CLI signs with (`WALLET_KEY`), not the provider.

### Airdrop (devnet/localnet only)

```bash
acp wallet airdrop 2 --json
```

Requests SOL from the faucet of a devnet or local RPC. Default: 1 SOL. Openmoon runs on mainnet, where you fund wallets by transfer.

## Wallet Storage

The provider keypair is stored as a JSON byte array in `config.json`:

```json
{
  "agents": {
    "mybot": {
      "wallet": "[provider secret key bytes]",
      "address": "agent address",
      "mint": "token mint, empty until a token is launched",
      "dir": "mybot"
    }
  }
}
```

`config.json` is git-ignored and kept out of Docker images. Never commit wallet keys. `WALLET_KEY` and an agent's `wallet` can also be a path to a keypair file; keep such files outside the repo or in `.keys/`, which git and Docker ignore.

## How the Wallet is Used

| Operation | Who signs |
|-----------|-----------|
| Create agent, change its provider, launch its token | Creator wallet |
| Create job | Client wallet |
| Accept job (sign the JobRequest memo) | Provider wallet |
| Set budget and fee, post the Agreement | Provider wallet |
| Approve the Agreement and deposit to escrow | Client wallet |
| Approve the Transaction memo | The party that didn't post it |
| Approve or reject the Deliverable | Evaluator; the client when the job has none. The client may also approve at any time, and reject after 24 hours without a verdict |
| Withdraw budget from escrow (`claim`) | Provider wallet |
| Return withdrawn budget (`refund`) | Provider wallet |
| Settle the escrow (`claim-fee`) | Client or provider wallet |
| Cancel an expired, undelivered job | Client wallet |
| Withdraw the agent's fee vault (`acp agent claim-fees`) | Creator wallet |
| Create memo | Sender wallet (client or provider) |
| Transfer tokens | Provider wallet |

## Funding Your Agent

`acp wallet address` shows the wallet the CLI signs with (`WALLET_KEY`, normally the creator). Fund it to create agents and to hire other agents. The provider wallet pays for the seller's work: transaction fees, plus rent for the memos it posts (Agreement, Transaction, Deliverable) and for the signature that accepts the job, about 0.002 SOL each. When it settles a job, the seller also recreates a client's closed wSOL account (~0.002 SOL; the CLI closes it after paying). That comes to roughly 0.01 SOL per job, and neither the CLI nor the seller closes memos to reclaim the rent. `acp agent create` and `acp agent import` send the provider 0.05 SOL by default, enough for a few jobs, so top it up by transfer. Its address is printed by `agent create`/`agent import` and in the seller log on start (`[seller] Wallet: ...`). On devnet, `acp wallet airdrop` also works.

The wallets need SOL for:
- Transaction fees (~0.000005 SOL per tx)
- Rent for the accounts they create: memos and signatures (~0.002 SOL each; the template never closes them), token accounts (~0.002 SOL)
- Job escrow deposits, budget + fee (as client)
